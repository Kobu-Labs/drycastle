# 04 Loot + tires

The stealing loop with the first target. Later targets (05 to 07) only add a target kind.

## Facts
- Cars are real `ServerCar` entities (`SpawnCars`, `NetServer.Vehicles.cs`), 12 of them; the server knows where they are.
- Vehicle record (`VehicleRecord.Make`, `VehicleRules.cs`): Health byte bits 0-1 damage stage, bit 7 lights, **bits 2-6 free**.
- `kenney-car-kit/sedan.glb` has nodes `wheel-front-left`, `wheel-front-right`, `wheel-back-left`, `wheel-back-right` (`CarFx.cs`). Other models name wheels differently or not at all.
- Hold-use with prompt and ring: the care package and the Rozhlas set.

## Do
- `LootKind` (Tire, Pet, Dish, Connector) and `StealTarget` (kind, position, work spot, id of the thing) behind one interface: `Free`, `Claim`, `Take`, `Return`. A registry lists free targets near a point.
- Thief states added to the member machine: Seek (pick the nearest free target of a random kind by weight, one Thief per target), Approach, Steal (`steal_seconds` per kind, a still target), Haul (to the van door, faster), Load (Loot counted in the van, Thief seeks again). Van called the crew back: drop nothing, board.
- `Loot : IWorldEntity` (new wire type) for lying Loot: kind, origin. Carried Loot is not an entity: the carrier's hp byte says what it carries, the client attaches the prop.
- Carrier killed: Loot lies where they fell. A Thief may pick lying Loot as a target. A player holds use `return_seconds` (1) on it: it goes back to its origin (`Return`). Interrupted by moving off or taking a hit. Cap `max_lying` (24): over it the oldest returns by itself.
- Van destroyed: everything loaded returns. Van driven off: gone until the round resets.
- After the event: lying Loot stays and stays returnable. Round reset: all restored.
- Crowding hook for 02: a player within `crowd_m` of a Thief in Steal or Haul gets aggro.
- Credit: a player who sent Loot back is credited for the event XP (10).
- Tire target: one per wheel of a spawned car at rest. `Take` sets the wheel bit (mask in Health bits 2-5), `Return` and `VehicleLifecycle.Reset` clear it. The car drives exactly as before. Work spot beside the wheel; kneel pose.
- Client: hide the wheel node by mask (sedan names; models without wheel nodes: nothing hidden, noted). Tire prop carried in both hands, lying tire, use prompt + ring per the UI standard (`ui-work` skill first).

## Accept
- Tests: target claim is exclusive; full loop Seek to Load; carrier death drops Loot at the spot; Thief re-takes lying Loot; player return restores the wheel bit; van destroyed returns all; cap; reset restores.
- Protocol bumped if the vehicle record meaning changed.

### How to add a target kind (05, 06, 07)
One class in its own file, one registration line, one json sub-section, one client stub. Nothing in the Thief states, lying Loot, the van's count, the return, the reset, the stop choice or the wire changes.
1. **Source class** in the kind's own file under `godot/ShooterCore/Thieves/` (`PetTarget.cs`, `DishTarget.cs`, `ConnectorTarget.cs` exist as stubs holding only the config class; add the class there): implement `IStealSource` (`TireTarget.cs` is the pattern). `Kind`; `FreeNear(near, radius, into)` and `Places(into)` list the free things (ground x/z for the van's stop choice); `TryFind(id, out target)` says whether it is still free and where it is now (called every tick while a Thief goes for it and works at it: false = the Thief gives up); `Take(id)` = the Thief has it (gone from its place); `Return(id)` = back at its place; `Reset()`. Optional (default interface members): `LiesWhenDropped` (false: a killed carrier does not leave lying Loot, the piece goes back at once through `Return`: pets) and `Carried(id, carrierAt, yaw)` (called every tick for a carried piece: pets move the animal there). Ids are the source's own `int`. Claiming (one Thief per target) is the registry's. World access goes behind a small interface (as `ITireCars`) so the source stays Godot-free and testable.
2. **`StealTarget(kind, id, Position, WorkSpot, Top = null)`**: `WorkSpot` is where the Thief stands (ground). A target that needs a climb sets `Top` (see the climb below).
3. **Registration, one line**: in `InitLoot()` of `godot/shooter/Net/NetServer.Thieves.Loot.cs`, replace the marked comment line with `registry.Register(new PetSource(...));` (markers for pets, dishes, connectors are there). The server adapter (the world access, like `ServerTires`) goes in a file of its own, `NetServer.Thieves.Loot.<Kind>.cs`, so the three tickets do not touch the same file. `RaidTargetPoints()` asks the registry (`LootPlaces()` = every source's `Places`), so the van's stop choice counts the new kind by itself.
4. **thieves.json**: the kind's sub-section of `loot` already exists (`"pet"`, `"dish"`, `"connector"`: `weight` (a Thief picks a kind by weight among the kinds with something free near, 0 = never) and `steal_seconds`); put its own numbers there and in its config class (`PetLootConfig : LootKindConfig` in the same stub file; override `Validate(file, kind)`, call the base first). `LootConfig.Of(kind)` finds it.
5. **Client stub**: `godot/shooter/LootProp.Pet.cs` / `.Dish.cs` / `.Connector.cs` each hold `Carried<Kind>()` and `Lying<Kind>()` (a small coloured box now); `LootProp.Carried(kind)` / `LootProp.Lying(kind)` are the switches and need no edit. The carried prop hangs in front of the chest (`GangMemberView.Loot.cs`, `CarryAt`); the string `loot.<kind>` for the use prompt exists.
6. **Tests**: a fake source as in `LootTests.cs` (`FakeClimbSource`, `FakePetSource`) in the ticket's own test file.

### Climb API (generic; used by 06 and 07)
- A target says it needs a climb by `StealTarget.Top` (a world point, normally straight above `WorkSpot`); `WorkSpot` is the base on the ground. `StealTarget.NeedsClimb`.
- Member states (replicated, `GangMemberState`): Approach to the base, then **ClimbUp** (moves in a straight line from the base to `Top` at `loot.climb_speed`, off the navigation mesh, yaw to the target), **WorkAloft** (clock: the kind's `steal_seconds`, standing at `Top`), **ClimbDown** (straight back to the base at `climb_speed`), then Haul with the thing (or Seek when it had none). All three are `Working` (crowd rule) and the member does not fight.
- Target gone (or taken) while it climbs or works: ClimbDown with nothing, then Seek. Called back (`Board`) or `Flee` while aloft: it is put on the ground at the base at once.
- Killed aloft: `GangMember.RestPoint` = the point under it on the ground (the base's height); it falls there at 9.81 m/s2 (Dead tick) and lies dead; `GangKilled.Where` and the Loot it carried (or the speaker) are at that ground point.
- Clip names `gang.view.clips.climb_up`, `climb_down`, `climb_work` (and `steal`, kneeling) in thieves.json, empty now: the client holds the pose (animation paused; Steal without a clip bends and lowers the body).
- Tested with a fake target (`LootTests`: heights, times at climb_speed, straight up, states in order, killed aloft falls and lies at the base, target gone aloft, called back aloft).

### Wire (protocol 47)
- World entity type **56 `loot`** (lying Loot): state byte = `LootKind` (0 Tire, 1 Pet, 2 Dish, 3 Connector), owner field = the low 16 bits of the origin id (tires: car id * 4 + wheel; the client only needs the kind), position = where it lies (ground), yaw = how it lies, no hp byte (`LootRules`, `LyingLoot`).
- Gang member states 9 Seek, 10 Approach, 11 Steal, 12 Haul, 13 Load, 14 ClimbUp, 15 WorkAloft, 16 ClimbDown. The hp byte's carried bits (3-5) now carry `LootKinds.CarriedOf` (kind + 1); the client draws the prop while alive.
- Vehicle record health byte: bits 2-5 = wheels taken (bit 0 front left, 1 front right, 2 back left, 3 back right), bit 6 still free (`VehicleRecord.Make(..., wheelsOff)`, `VehicleRecord.Wheels`). Lives in `VehicleLifecycle.WheelsOff` (`TakeWheel`, `ReturnWheel`).
- Raid van owner field bits 10-14 = song number (0-31, `RaidVanRules.SongOf`); the client plays song number modulo the songs it has.
- No new event kind (233-235 and 237-239 stay free). The send-back needs none: the server counts the use-key hold from the inputs.

### Decisions
- **Loop**: a Thief with `Work` (`ThiefGang.Work`, a `RaidWork` per Raid) goes Idle to Seek at once. Seek picks among free, unclaimed targets within `loot.seek_radius_m` (90) of the van: a kind by weight, then the nearest of it to the Thief; one Thief per target (claims are the registry's); retries every `seek_retry_seconds` (2). It picks only while the van is Opening or Parked and (loaded + Loot on its way) is below the capacity (no overshoot). Approach at 3 m/s (`approach_speed_mps`), gives a target up after 45 s or at once on a lost route (not chosen again for 60 s), Steal (`steal_seconds` of the kind; `pickup_seconds` 1 for lying Loot, a still target, Working), Haul at 4.5 m/s to the door (drops it after 60 s, or at once when the van takes no more), Load (0.6 s) into the van, Seek again. Lying Loot is a target of its kind (it competes with the kind's things by distance).
- **Fight**: a Thief in Seek or Approach has free hands and joins a fight (its claim ends); one in Steal, a climb state, Haul or Load is Working and Busy (crowd rule of 02 now fires, `crowd_m` 4). Called back (`Board`): drops nothing, boards; what it carries is tossed into the van at the door (`Raid.OnBoarded`); a van that cannot take it sends it back to its place. Flee (van destroyed or left without it): the claim ends, the Loot it carries goes off the map with it (stays stolen until the round resets).
- **Carrier killed**: the Loot lies where it fell (`LootBook.Drop`, `LyingLoot`, the source's `Take` stays done, so a tire's bit stays set until someone sends it back). Another Thief may take lying Loot up and carry it on; a player holds use `return_seconds` (1) within `reach_m` (1.8) of it, on foot: back at its place through the source's `Return`. Moving off the reach, switching to other Loot or releasing starts the hold over; a hit taken (health fell) ends it until the key is pressed again. Counted on the server from the inputs (`LootReturnHold`, next to the rozhlas hold), shown by the client from the same rule (the care package's ring and prompt line, `RadialProgress`). The use key does not enter a car while lying Loot is in reach (it would be a second meaning of the same press). Cap `max_lying` 24: the oldest goes back by itself.
- **Van**: destroyed returns everything loaded (`Raid` returns each piece through the book before it raises `LootReturned`); driven off keeps it (gone until the round resets). The loaded list is `Raid.Loaded`.
- **After the event**: lying Loot stays (it is a world entity of its own) and stays returnable; what is stolen stays stolen. A round reset restores everything (`ThievesRoundReset` to `LootBook.Reset`; the cars' own reset clears the wheel bits). A cancelled event (`/event current cancel`) also restores everything (it never happened). An admin's `end` keeps it as a win.
- **Tires**: a target per wheel of every car of `loot.tire.vehicle_ids` (`["car"]`: the sedan model) at rest (nobody inside, not thrown, not destroyed, slower than 0.5 m/s). Wheel centres 0.72 m either side and 1.12 m ahead and behind the car's origin (the sedan's wheel nodes at the game's scale 1.7), the Thief kneels 1.9 m out from the middle beside the wheel. A car driven off, entered or destroyed during the approach or the steal ends it. The wheel bit is set at the end of Steal, cleared by `Return`, by `VehicleLifecycle.Reset(repair: true)` (round start, return after destruction) and not by an abandon return (the car stays as it was, as it keeps damage). The car drives as before. Client: hides the node `wheel-front-left` / `-right` / `wheel-back-left` / `-right` of the model by the mask; a model without those nodes hides nothing (only the sedan is listed).
- **Credit**: `CreditedVanHits` wraps the vans' hit routing (`MatchSim.Vans`) like `CreditedGangHits`: any counted hit (not one the van ignored) calls `NoteVanHit`. `NoteLootReturned` when a hold completes, only while the event runs (the list is cleared at the end).
- **Van music**: the roster picks a song number at the van's birth (not one another living van has, when possible), it travels in the owner field; the client calls `PlayVanSong(van, song, serverSeconds)` with the server clock (tick / tick rate) so the loop is in step on every client and for a joiner; `StopVanSong` when the van is seen destroyed or despawned. Silence without songs.
- State machine docs regenerated (`GangMember.State` gets eight new states with their edges); every new state has a note.

### Open
- Not run in the game (brief): the work spot beside the wheel, the wheel centres (computed from the sedan's node positions: pivot plus half the wheel's width), the kneel pose, the carried tire in both hands, the hidden wheel, the prompt and ring, the approach and haul speeds and every number in `loot` are build- and unit-verified only.
- UI standard DoD not complete: the prompt and ring reuse the care package's HUD pieces (no new control, strings in `Strings.cs`), but there are no screenshots at 1280x720 and 3840x2160 and no keyboard walkthrough (brief: nothing run).
- Only cars of type `car` have tires (the sedan's wheel nodes are known); the jeep (`suv.glb`) and the others have not been checked for wheel nodes, so they are not in `vehicle_ids`.
- Approach and Haul follow the navigation mesh routes of 02; a route that ends within `repath_m` (3 m) of the work spot or door counts as arrived, so a work spot off the mesh by more than that is given up (avoided 60 s).
- A Thief called back or fleeing aloft is put on the ground at the base at once (no climb down).
- A kneeling capsule is bent forward and lowered; with Synty bodies the `steal` clip is empty (ticket 08 names one).
- Lying Loot does not expire and has no hit marker or outline; a tire lying next to the car it came from is just a prop on the ground.
- The send-back hold uses the use key (E) like entering a car: with Loot in reach the car-enter press is swallowed, so a tire lying within 1.8 m of a car blocks entering it until it is sent back or moved away.
