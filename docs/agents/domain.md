# Domain docs

Single-context repo: one `GLOSSARY.md` and `docs/adr/` at the root.

- Before exploring, read `GLOSSARY.md` and the ADRs touching the area you work in. If a file is missing, proceed silently.
- Use the glossary's terms (issue titles, proposals, tests); do not drift to the synonyms it says to avoid. A missing concept is either invented language (reconsider) or a gap (note it for `/domain-modeling`).
- If your output contradicts an ADR, say so explicitly rather than overriding it silently.
